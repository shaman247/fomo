# Build System Details

## City config injection

`build.js` reads `config/<FOMO_CITY>.yaml` (`process.env.FOMO_CITY || 'nyc'`, parsed with the `yaml` devDep) and injects its `frontend:` block at build time:

- **Runtime JS** — a `;window.__CITY__ = {map, timezone};` prelude is **prepended** to the concatenated bundle (before flatpickr) so the global exists before any IIFE evaluates. `src/js/script.js` (`App.config` map fields) and `src/js/core/utils.js` (timezone) read it.
- **Branding** — `applyBranding()` replaces `{{SITE_NAME}}`, `{{DOMAIN}}`, `{{EMOJI}}`, `{{WELCOME_MODAL}}`, `{{DESCRIPTION}}` and `{{SHARE_IMAGE}}` tokens in `src/index.html`. The last two feed the `<meta>` description and the Open Graph/Twitter link-preview tags, are HTML-escaped, and come from `frontend.description` and `frontend.share_image`, a 1200×630 PNG under `src/` regenerated from the live map by `scripts/generate_share_card.py`. `src/robots.txt` is copied as-is (crawlers are allowed everywhere except `/api/` and `/admin/`) (runs last; the build **fails** on any leftover `{{TOKEN}}`). `src/about.html` is copied as-is (not tokenized).
- **Home-screen install** — `webManifest()` writes `dist/manifest.webmanifest` (name, `short_name`, relative `start_url`/`scope`/`id` so it works at the root and under XAMPP, `display: standalone`, `theme_color` as theme and background colour, icons). `{{SHORT_NAME}}` and `{{THEME_COLOR}}` fill the `apple-mobile-web-app-title` and `theme-color` tags in `index.html`. Icons are `src/images/apple-touch-icon.png` (180) and `app-icon-192/512.png` + `app-icon-maskable-512.png`, generated with the native app icons by `scripts/generate_app_icons.py`. Their URLs get `?v=<md5>` from `versionedAssetUrl()` (they would otherwise stick in the SW's cache-first runtime cache), and `checkIconSize()` fails the build on a missing or mis-sized icon. `apple-mobile-web-app-status-bar-style: black-translucent` runs the iOS standalone app edge to edge like the native app, so the panels' `env(safe-area-inset-*)` padding applies. The app's theme is user-chosen, not system-driven, so `themeManager.js` swaps `theme-color` to `frontend.theme_color_light` (via `window.__CITY__.themeColors`) while the light theme is on.
- Dev watch includes `config/<FOMO_CITY>.yaml`, so config edits rebuild.

## JS Build

- JS modules use IIFE pattern with globals — they are **concatenated** (not bundled) then minified via `esbuild.transform()`. esbuild's bundler mode would break global scope.
- `build.js` reads `src/index.html` to determine JS file order — no separate manifest
- flatpickr installed via npm, prepended to JS/CSS bundles; the `window.__CITY__` prelude sits before flatpickr
- MapLibre is NOT in the bundle: `src/vendor/maplibre-gl.mjs` + `maplibre-gl-worker.mjs` (copied from the npm tarball's `dist/`; its `maplibre-gl-shared.mjs` is empty and not needed) load through an inline module script in `index.html`. To upgrade, replace both `.mjs` files and the CSS, then bump every `vendor/maplibre-gl*?v=` in `index.html`. `checkMaplibreVersion()` fails the build unless all of them equal the version in the vendored file's license banner, and `src/.htaccess` serves `.mjs` as `text/javascript` (module scripts and module workers need it).

## CSS Build

- CSS `@import` chain resolved and minified via `esbuild.build()` with `bundle: true`
- Font path rewrite: `../fonts/` → `fonts/` (CSS moves from subdir to root in bundle)
- Font URL versioning: `versionedAssetUrl()` appends `?v=<md5(content)>` to every `fonts/*.woff2|ttf` URL in the CSS bundle AND to the font entries in the SW precache manifest (same helper, always in sync). Font filenames are stable but 1-year-cached and SW-precached as immutable — without the version query, changed font bytes (e.g. re-frozen OpenType features via `scripts/freeze_inter_features.py`) would never reach returning visitors.

## Dev vs Prod

- Dev (`npm run dev`): unminified, stable filenames, symlinks `data/`, `images/`, `fonts/`, `api/`, `admin/`, `vendor/` from `dist/` → `src/`
- Prod (`npm run build`): minified, content-hashed filenames, copies those directories into `dist/`

## Generated-data fallback

`src/data/tag_hierarchy.json` is regenerated by every pipeline run, so it's **gitignored**. A committed `src/data/tag_hierarchy.example.json` is the fallback. `build.js` (`EXAMPLE_DATA_FILES` → `ensureSeededData()`) copies the example to the live filename **only if the live file is absent** (fresh checkout / fork with no pipeline export yet) — a real export always wins. `*.example.json` files are skipped when copying into `dist/`, so they never ship. To refresh the fallback, copy the current live file over the example and commit it.

## Deployment

```bash
npm run build                          # Build to dist/
python scripts/upload_public_html.py   # Upload dist/ to server via FTP
```

The upload script tracks file content hashes (MD5) in `scripts/upload_state.json` and only uploads changed files. Use `--force` to upload everything.

**Frontend gate**: when the app bundle changed since the last upload (a new `app.<hash>.js` name, or a different `index.html` hash), the upload first runs `npm test` (every `src/js/tests/*.test.cjs`) and `scripts/frontend_smoke.py` (headless Chromium over DPR 0.9–2, three device timezones and a mobile viewport: fails on any page/console error, blank map sprites, event times that differ from a New-York-device run, or a missing ErrorReporter beacon) and uploads nothing if either fails. Data-only uploads skip it. `--skip-frontend-checks` overrides. Run the smoke alone with `./venv/bin/python scripts/frontend_smoke.py [--dist DIR] [--only dpr-1.25,tz-london]`.

**Client error reporting**: `src/js/core/errorReporter.js` (after `beacon.js`, the shared device-context/sendBeacon helper both beacons use) beacons uncaught errors, unhandled rejections and `console.error` calls (max 5 per page load, deduped per session, URLs cut to file names) to `api/client_errors.php`, which appends to a log outside the web root. Summarize with `./venv/bin/python scripts/client_errors.py [--days N] [--bundle HASH]`. It shows only new or recurred error signatures, which stay stable across deploys. Record verdicts with `--mark SIG --verdict ignored|backlog|fixed --note …`, stored in the local `.claude/client-error-triage.json`, and use `--show SIG` to inspect one. A weekly review procedure is in `.claude/recurring-checks.md` ("Weekly: Review client error reports").

**Analytics**: `src/js/core/analytics.js` sends a `view` beacon on load, a `timing` beacon when the markers first appear (the `fomo:markers-visible` performance mark `script.js` sets after `_showMainUI()`, with `detail.source` network or cache; `markersMs: null` if the page is hidden first; bucketed by `analytics.php` into `markers_network`/`markers_cache`), and an `engage` beacon (visible seconds, feature-use counts from delegated DOM listeners, first-use flags) each time the page is hidden. It runs only on `frontend.domain` (never in dev or the smoke test) and is off under Do Not Track/GPC. `api/analytics.php` (shared helpers in `api/beacon_lib.php`) only adds to daily counter files. Automated traffic is identified by `beacon_traffic()`: a bot or tool UA, `navigator.webdriver`, or a phone UA at a desktop-size viewport or screen, as with link-preview renderers. It is kept in each day file's `automated` section and never mixed into the real totals; `client_errors.php` tags every log line `traffic`/`traffic_reason` and caps each class separately, and `scripts/client_errors.py` shows real traffic unless `--traffic automated|all`. Totals live in `<parent of DOCUMENT_ROOT>/analytics/YYYY-MM-DD.json`, in city-timezone days. No per-visit rows, no IPs, no visitor counting (a deliberate choice, disclosed in `privacy.html`). The native apps are reported as `ios-app`/`android-app` through `frontend.native_app_ua`. To add a tracked action, add it to `CLICKS`/`CHANGES` in analytics.js, `ACTIONS` in analytics.php and `ACTIONS` in `scripts/analytics_report.py`. Report: `./venv/bin/python scripts/analytics_report.py [--days N] [--html] [--note TEXT]`. `--html` writes the local, gitignored dashboard page `.claude/analytics-dashboard.html` (inline CSS/SVG, no network), and `--note` adds dated review notes to it. A weekly review updates it (`.claude/recurring-checks.md`, "Weekly: Review analytics and update the dashboard"). It never uploads `dist/data/similarity/`: a similarity model generation goes live only through the gated `pipeline/similarity_publish.py` (procedure in `pipeline/similarity.md`).

## Service worker emission

`build.js` `emitServiceWorker()` renders `src/sw.js` (a template — never served as-is) into `dist/sw.js`, injecting the precache manifest (hashed bundles + versioned vendor + fonts + map styles + `manifest.webmanifest`) and a version hash so any shell change reinstalls the precache. The web app manifest is revalidate-class and its bytes feed the version hash, because browsers re-read it to update an installed app; the install icons are versioned URLs but are not precached (only needed online, at install). Data JSONs are deliberately NOT SW-cached — the page owns them in IndexedDB (`src/js/data/dataCache.js`). Controls:

- **Dev builds and `frontend.sw_enabled: false`** emit a self-unregistering "killer" sw.js (activate → wipe all SW caches + unregister; IndexedDB untouched) and set `window.__CITY__.swEnabled = false` so the page doesn't register. This is also the production rollback path — deploy a disabled build's sw.js, no app-store release needed.
- `src/.htaccess` serves `sw.js` with `Cache-Control: no-cache` (mandatory — the blanket 1-year JS rule would otherwise freeze SW updates).
- `sw.js` sits at the dist root; the index.html JS-concat regex only matches `js/…` paths, so it never joins the app bundle.
