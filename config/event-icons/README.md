# Event icon catalog

For repeatable discovery, design, review, and database-backed integration, follow the [custom icon workflow](workflow.md). The [Fomo custom-icons skill](fomo-custom-icons/SKILL.md) routes future batches through that process.

Every new or materially changed icon runs through [automated critical visual review](visual-review.md). `render-review.py` produces reproducible browser-rendered evidence; the agent critiques it and revises defects before integration. Final review records live in `reviews/` and refer to exact source hashes.

`catalog.json` defines semantic IDs, accessible labels, Unicode fallbacks, and artwork sources. `art/` contains custom Noto-style SVGs, including original geometry and explicitly credited Noto component adaptations. They are not official Google or Wizards event icons. Pinned upstream Noto assets live separately in `noto/` and `noto.json`; both providers use the shared renderer. Batch provenance and acceptance records live in `reviews/`.

The palette and shading were guided by Google Noto dice, Mahjong, flower cards, wood, yoga, and cartwheel references. References and their original Apache 2.0 license are preserved in the local design study at `design/event-icons/noto-prototype/reference/`. Upstream: https://github.com/googlefonts/noto-emoji/tree/main/svg. The MTG-inspired card uses a redrawn Planeswalker-inspired emblem and is scoped to Magic: The Gathering; it must not be used as a generic trading-card pictogram. The symbol reference is https://magic.wizards.com/en/news/announcements/venturing-outward-new-magic-logo-2018-03-27.

The 35-icon weekly expansion adds instrument, craft, equipment, game and ensemble pictograms. `brass-band.svg`, `big-band.svg` and `jazz-piano-trio.svg` adapt components from the pinned Google Noto Emoji revision in `noto/NOTICE`; modifications compose and scale the instruments and add an original bass-clef symbol. Their Apache 2.0 attribution is retained in SVG comments and the bundled notice. The other 32 new sources use original geometry. Ensemble pictures are representative family cues, not a promise of an exact performing roster. Card-game and closely related instrument distinctions are strongest at 24–32 px; consult the hash-bound review records for 16 px limitations.

Run `node config/event-icons/build.cjs` after editing art or metadata. The normal site build also calls this generator. It emits content-hashed SVGs into `src/images/event-icons/` and `src/js/core/eventIconCatalog.js`. These outputs are gitignored; commit the source artwork, catalogs, and licenses under `config/event-icons/` instead. A fresh checkout needs `npm run build` (or the icon generator alone for direct source previews) before serving icons. Run the generator with `--check` after generation to verify outputs are current.

Keep older hashed assets available while cached clients may still reference them. The generator retains existing hashes locally, and the FTP uploader adds or updates files without deleting older remote assets. A fresh checkout regenerates only current hashes, so deployments must preserve existing remote icon files rather than mirror-delete them.

`packs.json` defines stable transport groups, independently of daily event exports. The `startup` group contains common chip, UI and event artwork and is requested when the renderer initializes. Other packs load when a render batch requests at least two distinct member icons whose combined individual gzip sizes cover at least 60% of the pack's gzip size. Isolated requests and unassigned artwork load individually. A downloaded pack is reused for later requests. The build generates `icons-<group>.<hash>.json` alongside the individual SVGs. Each JSON pack preserves the source SVG text and per-icon revision, so existing canvas rendering, theme transforms and color extraction still use the same artwork. Only requested icons are decoded.

The startup pack is capped at 384 KiB uncompressed. Other groups are split into packs of at most 128 KiB; an individual SVG larger than that remains standalone. Keep membership stable and tune it from measured first-screen demand instead of regenerating it from each day's rankings. Editing artwork changes only its containing pack's hash. Pack responses use a one-year immutable cache policy. Missing, malformed or stale packs fall back to individual files; a failed pack is attempted once per page, and the embedded fallback remains the last resort. Publish new packs before their referencing bundle and retain old hashes for cached clients. Pack generation is offline and requires no database access.

`preview.html` is a template, rendered by `pipeline/event_icon_report.py`; it is not a production page. It uses the actual shared popup/list event card and theme/color code. See `pipeline/event_icons.md` for assignment, export, rollback, report, and test commands. The active city config controls production rendering.

For per-icon artwork feedback, run `./venv/bin/python config/event-icons/viewer/serve.py` and open `http://127.0.0.1:8768`. The local [custom icon viewer](viewer/index.html) loads the custom catalog plus the current jazz prototype, with search, status filters, light/dark backgrounds, actual-size samples, and larger inspection. Rate each icon **Looks good**, **3D redo**, or **Unsure**, and add notes. In inspection, use arrow keys to browse and 1/2/3 to rate; shortcuts are inactive while typing notes. Ratings remain on screen while writing notes; changing filters or closing inspection refreshes the gallery.

Feedback autosaves to `.scratch/icon-viewer/feedback.json` with stable icon IDs, source hashes, notes, and timestamps; the page reports save failures and offers retry. Export feedback downloads a portable JSON copy. Changed artwork is marked for review again on the next server start. Use `--port` or `--feedback PATH` for a separate review session. The server binds only to loopback and serves an explicit list of viewer/asset routes. It does not publish a page or modify artwork, assignments, or the database. Restart it after adding or changing icons, and use the feedback file as input to a separately requested redo batch.
